## Profile source comparison

The checked-in JSON and the former Kotlin production mirror agreed on profile IDs, boot modes, artifact IDs, disk sizes, initialization kinds, recovery SSH, and most minimum requirements. The mirror nevertheless omitted three Ubuntu qualification checks present in canonical JSON:

- `virtio-block`;
- `virtio-net`;
- `serial-console`.

The JSON also carries fixed compatibility fields that the mirror did not read from data: architecture `aarch64`, machine family `virt`, acceleration `tcg`, PCI device transport, primary network `slirp`, recovery guest port `22`, recovery bind `loopback`, and raw data-disk format. The packaged parser now validates those values instead of silently discarding alternatives.

## Artifact manifest inventory

Before F01, the same active manifest was interpreted independently by:

- controller upload publication and moved-payload recovery;
- public HTTPS import publication, installed checks, and interrupted-publication cleanup;
- Host API image listing;
- QEMU runtime artifact resolution.

Each parser checked a different subset of fields or payload properties. F01 selects one strict adapter requiring the exact versioned fields, digest, size, immutable relative path, payload size, and root containment. Expensive digest verification remains explicit at trust boundaries rather than hidden in every listing call.

## Selected implementation

- Generate Android assets from the exact checked-in profile JSON and rendered trusted guest-init sources.
- Verify the APK contains byte-for-byte canonical profile, schema, index, and guest-init assets.
- Parse only the three qualified profiles from bounded immutable APK assets and map them to existing typed domain values.
- Validate fixed Android/QEMU compatibility constraints during parsing: AArch64, `virt`, TCG, PCI virtio transport, SLIRP, and loopback recovery SSH on guest port 22.
- Use profile-derived artifact IDs and boot type for disk preparation rather than a profile-ID-to-artifact mirror.
- Resolve guest vendor data through the selected profile instead of profile-specific Kotlin branching.
- Use `ArtifactManifestStore` for publication, listing, cleanup, installed checks, and QEMU consumption.
- Preserve legacy direct files plus `.sha256` metadata only for the pinned Podroid qualification assets until native artifact publication is migrated separately.
