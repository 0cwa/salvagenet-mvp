## Profile source comparison

The checked-in JSON and former Kotlin production mirror agreed on profile IDs, boot modes, artifact IDs, disk sizes, initialization kinds, recovery SSH, and most requirements. The mirror omitted three Ubuntu qualification checks present in canonical JSON:

- `virtio-block`;
- `virtio-net`;
- `serial-console`.

The JSON also carries fixed compatibility fields the mirror did not read from data: architecture `aarch64`, machine family `virt`, acceleration `tcg`, PCI device transport, primary network `slirp`, recovery guest port `22`, recovery bind `loopback`, and raw data-disk format. The packaged parser validates those values rather than discarding alternatives.

## Artifact manifest inventory

Before F01, the same active manifest was interpreted independently by:

- controller upload publication and moved-payload recovery;
- public HTTPS import publication, installed checks, and interrupted-publication cleanup;
- Host API image listing;
- QEMU runtime artifact resolution.

F01 selects one strict adapter requiring exact versioned fields, digest, size, immutable relative path, payload size, and root containment. Expensive digest verification remains explicit at trust boundaries.

## Implemented boundary

- Generate Android assets from the exact checked-in profile JSON and guest-init sources.
- Verify the APK contains byte-for-byte canonical profile, schema, index, and required guest-init assets.
- Parse only the three qualified profiles from bounded immutable APK assets into existing typed domain values.
- Validate AArch64, `virt`, TCG, PCI, SLIRP, recovery SSH, and vendor-data path constraints before side effects.
- Use profile-derived artifact IDs and boot type for disk preparation rather than a profile-ID mirror.
- Resolve guest vendor data through the selected profile.
- Use `ArtifactManifestStore` for publication, listing, cleanup, installed checks, and QEMU consumption.
- Keep bare-file plus `.sha256` resolution only for the three pinned Podroid qualification artifacts.
- Require active manifests for Ubuntu, AAVMF, and every other non-Podroid artifact.

The repository briefly included a pre-F01 Ubuntu/AAVMF migration path during review hardening. It was removed immediately after F01 because the application has no deployed installations and therefore no real state to migrate. Keeping that code would add untested lifecycle and recovery complexity without user value.

## PR #7 review findings

The automated review produced valid actionable findings, all addressed on the final implementation:

- Gradle profile tooling paths are module-relative and do not depend on which settings root includes `node-shell`.
- Runtime vendor-data validation rejects empty, `.` and `..` path segments before `AssetManager` access.
- `ArtifactManifestStore.listActive` ignores invalid stray filenames and a remove-after-list race, while still failing closed for malformed valid manifests and for the explicit active-manifest count invariant.
- Manifest temporary tags are validated before filesystem mutation.
- Disk preparation resolves and verifies each source artifact once per preparation, reuses the typed result, copies with a 1 MiB buffer, and verifies copied bytes while streaming.
- Alpine direct-kernel/legacy-vendor, traversal rejection, exact profile cardinality, invalid manifest filenames, and explicit same-length digest-mismatch preconditions have regression coverage.
- F01 documentation uses consistent guest-init wording.
