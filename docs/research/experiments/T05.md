# T05 experiment notes

## Pinned source

- Android repository: `https://github.com/tailscale/tailscale-android.git`
- Android commit: `68dd0a5170999fa33c884cb58a8d1679234cc9a3`
- Core tag/commit: `v1.98.2` / `34c530668cb05fa60b3d707a44b70460344789ef`
- Toolchain measured: standard Go 1.26.3, JDK 17, Android API 36, min API 26.
- `tools/vendor/build-libtailscale-android.sh` produced an ARM64 AAR from a
  clean ignored build directory. The standard Go fallback was used instead of
  upstream's patched-runtime `tailscale_go` optimization tag.

## Verification results

- `make validate`: passed after removing ignored upstream build sources from
  the shellcheck search tree.
- `cd android/podroid && ./gradlew :mesh-tailscale:testDebugUnitTest`: passed;
  this also reproduced the AAR from an absent vendor build directory.
- `cd android/podroid && ./gradlew :mesh-tailscale:testDebugUnitTest :app:assembleDebug`:
  mesh compilation progressed, but app assembly failed in the out-of-scope
  `control-api` module because `MvpControllerAuthenticator` imports missing
  `org.nodehost.core.SecretValue`.
- `tests/network/host-mesh/smoke.sh`: official AAR structure passed; physical
  smoke skipped because app assembly did not produce an APK.

## Device evidence

No physical Android device VPN approval, service restart, socket protection, or
live Headscale enrollment was run. Those claims remain unverified. T05's
allowed paths do not include the `node-shell` composition hook that must create
`LibtailscaleHostMesh` and pass imported enrollment to it; fake and adapter
unit tests verify that mapping in isolation.
