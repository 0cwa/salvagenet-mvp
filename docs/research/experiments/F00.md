## Complexity assessment

The product architecture is not inherently overcomplicated for its goal: durable Android lifecycle, two independent mesh identities, typed remote management, QEMU guest execution, and recovery require real boundaries.

The development plan had become overcomplicated by keeping multiple future tasks active before their prerequisites and exact acceptance value were known. The correction is procedural rather than a large rewrite:

- one active phase;
- one cohesive foundation when sources of truth are split;
- queued future packets as hypotheses;
- explicit phase entry and exit criteria;
- physical diagnostics during development, but one final exact-candidate evidence seal.

## Selected foundation

F01 precedes additional host-QEMU and emulator expansion because it makes all environments exercise the same profile and artifact semantics. Without F01, a lab pass can validate checked-in JSON while the APK executes a Kotlin mirror.

F01 explicitly does not include:

- true qcow2 backing semantics;
- project-owned native source builds;
- UI or language rewrites;
- controller replacement;
- process isolation;
- H02/H03 implementation;
- USB/AOA work.
