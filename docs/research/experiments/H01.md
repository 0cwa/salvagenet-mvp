# H01 experiment record

## Status

The selected protocol has a first implementation on `agent/H01-artifact-upload` in commit `1567b6694dd642a6606f62ec70965be4019cd88c`. This record includes both the selected semantics and the hardening findings that must be closed before merge.

## Selected MVP semantics

- Controller-to-host uploads are authenticated resources separate from public HTTPS imports.
- Uploads are sequential, resumable, and exact-replay idempotent.
- Chunks are limited to 1 MiB and carry their own SHA-256.
- Progress metadata and payload bytes are fsynced and stored under app-private staging paths.
- Completion verifies the whole expected size and digest before publishing the existing digest-addressed payload and active-manifest layout.
- Cancellation never deletes a completed/active artifact.
- The controller derives deterministic upload idempotency from artifact ID, digest, and size, and resumes from host-reported committed bytes.
- The hardened public URL importer and its SSRF/DNS-rebinding policy remain unchanged.

## Implemented API surface

```text
POST   /v1/artifact-uploads
GET    /v1/artifact-uploads/{id}
PUT    /v1/artifact-uploads/{id}/chunks/{offset}
POST   /v1/artifact-uploads/{id}/complete
DELETE /v1/artifact-uploads/{id}
```

The implementation also advertises `image.resumable-upload` and adds corresponding controller CLI/client operations.

## Hardening findings

### Publication recovery

The implementation must treat payload movement and active-manifest publication as a recoverable transaction. A restart after the payload reaches `versions/<artifact>/<digest>/payload` but before the manifest is written must finish publication or return a deterministic recoverable state; it must not strand a valid payload behind an open upload.

### Bounded staging lifecycle

Cancelled and stale upload directories must be removed under a bounded policy. Merely marking uploads cancelled allows dead staging records to consume the maximum upload count indefinitely.

### Resource semantics

- Unknown upload IDs are `404 Not Found`.
- Offset gaps, partial overlap, conflicting replay, completion-before-full-size, completed/cancelled mutation, and idempotency-key reuse are `409 Conflict`.
- Malformed IDs, invalid digests, negative offsets, and oversized chunks remain `400 Bad Request`.

### Persisted metadata

Recovery must require the exact metadata field set and supported version. Unknown or future versions fail closed rather than being interpreted as current state.

### Existing publication checks

An existing active manifest must have exactly the expected version, digest, size, and relative payload path. Upload creation should not rehash a large already-published payload when trusted manifest metadata plus exact file size already establish the requested immutable digest path.

### Shared publication arbitration

Resumable upload and public HTTPS import publish into the same active-manifest namespace. Their publication must be serialized or governed by an explicit deterministic conflict rule; undocumented last-completion-wins behavior is not acceptable.

## Deferred beyond H01

Parallel/out-of-order chunk upload, TUF, OCI transport, distributed upload mirrors, content-defined chunking, and multi-controller cooperative transfer are not required for the one-phone MVP.
