# H02A — Canonical Ubuntu guest boot qualification

## Status

**PLANNED.** Phase-start review completed after F01 merged at `246d551ca7e691a0319a4b30e29d6e4905cd9910`. No host-QEMU qualification result is recorded yet.

## Question

Can the exact canonical Ubuntu profile and required guest-init inputs used by the Android package boot repeatably under Linux host QEMU, reach a real running QMP monitor, complete NoCloud, accept only key-based loopback SSH, survive restart, and erase one-use bootstrap material before guest mesh behavior is introduced?

## Evidence class

`host-qemu`; never Android, emulator, or physical evidence.

Required evidence fields include:

- source commit and dirty state;
- canonical profile identity and digest;
- Ubuntu/AAVMF artifact digests and sizes;
- QEMU, firmware, kernel, cloud-init, and SSH versions where observable;
- QMP status;
- cloud-init completion;
- password-authentication policy and key-only SSH result;
- guest reboot and QEMU stop/start results;
- bounded secret-residue scan result;
- cleanup result;
- `androidHardwareValidated: false`;
- `physicalGateEligible: false`.

## Boundary decision

Headscale and Tailscale enrollment are excluded. A guest image/bootstrap failure must be distinguishable from a mesh failure, so guest mesh qualification remains H02B and cannot be activated until H02A passes its phase-end review.
